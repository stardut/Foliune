## 原则、架构与验收判断

- 原则：真实文件复制、格式解码验证、逐项错误、原件保留和事务内元数据修改路径已存在，没有用浏览器 mock 代替桌面存储。上述两项修复前不能把阶段 1 清单标为全部完成。
- 架构：文件/照片、分组规则、SQLite 和 IPC 职责分开；同一照片跨组废弃只更新目标关系，SQL 条件包含 group_id 与 photo_id。元数据 patch 只允许白名单字段，失败时事务回滚；文件导入单项失败会清理本次管理副本。没有发现置信度达到报告门槛的额外架构问题。
- 权限与图像：capability 限定 main 窗口、core 默认权限和文件选择；asset scope 仅应用数据目录 originals/thumbnails，CSP 允许 asset/http://asset.localhost/data/blob 图片，TS 使用 convertFileSrc。静态配置相互匹配，最终 WebView 图片读取仍需真实桌面运行验收。
- 浏览器与错误态：API 在非 Tauri 环境主动拒绝，页面明确展示桌面提示；load 和 mutation 失败进入可见错误态，不回退为空库。文件缺失是上述 P1 中尚缺的错误路径。
- 内存与原子性：导入在 spawn_blocking 中逐文件处理，没有预先把整批图像全部解码进内存；单张仍需完整解码。此次未做高像素图像内存实测，不声称已验证性能上限。批量恢复的原子性问题见 P1；其他单次 SQL 更新与元数据失败回滚路径未发现确定问题。
