# 场景卡片阅读顺序整理

本记录保留场景与初轮纵向镜头整理；用户后续指出镜头仍缺主次，当前镜头布局见[镜头阅读焦点](planning-shot-focus.md)。参考图与场景参数布局继续保留。

2026-11-03，用户指出应用内场景参数的双列过于松散，镜头四列表格及嵌套标签使阅读横向跳转。本轮只整理应用内场景卡片，连续白纸 PNG 保持现状；不改数据字段、持久化、图库内容和全案其它区域。

## 方案

保留单层中性深色场景卡片、标题旁拍摄时段，以及左参考、右参数的上区。参考图继续完整呈现，逐图意图紧邻图片；单图保留较窄参考列，二、三图沿用既有比例。参数无论参考数量都统一为单列标签和值，不因单图或零图分散为多个参数列；窄窗转上下布局后仍保持单列。

镜头清单移除表头和四个横向大列，改为逐条纵向阅读：编号、名称、优先级在同一标题行；关键拍法紧随，构图、姿态、光线、情绪以两列紧凑标签行接续，窄窗降为一列。旧参考要点作为条目末尾的次要纯文字完整保留。自由补充清单置于结构化镜头之后，回到场景内容起点，以 14px 组间距及现有「补充清单」短标签表明属于场景，避免被读成最后一个镜头的补充；没有结构化镜头时仍直接阅读，不重复标签。条目间只用既有细分界及间距，不新增卡片、折叠、图标或说明文案。

编辑沿用同一信息顺序和字段对齐，复用 PlanField、排序和删除控件；全部可编辑字段保持挂载，清空后可继续输入。保留稳定 ID、添加后焦点、删除确认、容量限制和未保存保护。

## 验收依据

执行类型检查和现有策划内容、PNG、断行测试，确认未碰导出与数据契约。独立原生验收检查宽窄窗、1/2/3 张横竖方参考、长镜头和缺省字段，检查标题→拍法→细节→旧要点→补充清单的连续顺序，以及编辑清空续写、排序、删除确认、保存和取消。截图、实例、步骤、结果与限制由主代理补充，构建通过不计视觉通过。

本轮以稳定对齐、连贯阅读、完整摄影构图和克制的条目节奏落实高级及设计质感，不改变既有系统玻璃、字体或卡片材质。

## 本轮验证

类型检查、现有内容/导出/断行Node38/38及macOS release构建通过，独立审查者复跑38/38并按冻结3文件复核。预审发现后置补充清单会误归末镜头，已仅在结构化镜头之后恢复现有短标签、去镜头缩进并加14px组距；修正后重新构建。最终资源 `index-D9pdyH0v.js` / `index-DaVbCOt1.css`，保留既有混合导入与chunk体积提示。

Avenil管理隔离实例 `app.foliune.scene-review`，71张真实摄影图库，实际1320×880宽窗与921×928窄窗查看首场单图、第二场三图和执行末尾。主代理及独立验收者复核截图：参数单列、镜头纵向阅读清楚，优先级与名称同行，旧要点完整；补充清单在全场起点独立成组，三区边界、照片完整构图与深色卡片材质保持，无裁字覆盖。921px详情仍为两列，实际样本可读，不强改断点增加单列高度。

原生临时编辑中清空补充清单后焦点与入口保留，继续输入三行正常；新增镜头自动聚焦名称，长拍法完整换行、自增高；含内容镜头删除弹确认，取消后保留；实际前移临时镜头后名称/拍法/优先级/详情对应不乱。临时去掉第三张参考形成两图，截图只覆盖意图、详情和末尾，未据此宣称完整两图构图通过。最后取消编辑并选择放弃修改，恢复原有镜头、清单及三图。

`.build/verification/planning-scene-reading/` 保留用户参考、宽窗首卡、窄窗两场景、多镜头长文编辑、两图编辑局部、排序AX记录、两次构建日志、测试日志及 `integrity-final.json`。完整性核对：两份策划所有字段含JSON及时间戳、71份原件SHA256、71条相簿关系与基线完全一致，SQLite完整性ok/FK0；两PNG导出模块及内容/数据类型SHA不变。未修改导出、持久化或Rust，不重做无关导出/后端实测。

本轮以稳定单列参数、镜头连续阅读与补充归属改善高级感和质感，不新增底板、装饰或重复说明；独立设计验收通过不等于用户最终审美确认。完整两图及方图构图、<=760px详情单列分支、保存重开、完整键盘和异常、Windows本轮未新增原生验证；临时编辑长文不计为阅读态多镜头实测。
