# 策划场景卡片与整组准备

## 本轮场景与设计意图

用户在阅读整份人像策划时，需要先确认全案固定的妆造、道具和器材，再逐场景查看参考、参数与镜头。历史真实界面截图 `planning-compact/final-wide-single.png` 和 `final-wide-three.png` 中，场景仅以长横线分开，参考与参数缺少明确区名，场景边界和内部阅读顺序不够清楚。

本轮保留中性深色、连续外壳和完整摄影构图，以有可见细边界的浅层卡片区分场景。这是用户最新明确要求，优先于旧方案减少内容底板的取舍。卡片只承托完整场景，不再为参考、参数、镜头分别套底板；不改导航、系统材质或全局组件。

## 信息与交互方案

- 整体视觉之后、拍摄安排之前新增「整组准备」。妆造、道具、器材在宽窗并列三列，窄窗纵排；编辑可直接填写，阅读只呈现已填项，全空时整个区域不占位。
- 每场景使用 16px 圆角、18px 内边距、低对比中性浅底与细边界，场景间 16px。编号、名称与拍摄要点紧凑组织在卡片顶部。
- 上方以「参考图」「拍摄参数」明确分区：单图保持约 300px 宽参考列，多图采用约 2:1 参考/参数比例；图片舞台 156px，使用 contain 保持完整构图。参数正文保持 13px，以对齐标签行组织。
- 下方「镜头清单」全宽展开，用一条细分界与上区分隔。镜头名称列保持 150–190px 起点，其余有内容的列按比例分配；窄窗按镜头分组纵排，不引入折叠。
- 原场景造型与道具内容保留并以「场景补充」继续阅读、编辑；每次进入编辑时固定旧非空场景的展示资格，清空后输入框仍保留并可继续填写。为空的新场景不展示该编辑项，不自动迁移旧文字到整组准备。
- 沿用既有添加、排序、删除确认、保存禁用、参考选择和焦点恢复机制。新增字段复用 PlanField，不增加加载状态或保存路径。

## 验收依据与边界

静态检查与类型检查覆盖新增字段接线、空态隐藏、旧内容可达和响应式选择器。真实桌面验收由独立验收者检查宽窄窗口、单图/三图、首尾场景、编辑保存及键盘路径，保留截图；构建成功不作为视觉通过依据。

「高级」与「设计感和质感」落实在清楚的场景轮廓、统一中性色、克制形态、稳定对齐、足够可读的正文与照片完整构图。本记录是实施方案，真实界面效果仍须原生验收，不预先声称通过。

## 本轮实施与验证（2026-11-03）

全案新增styling/props/equipment三项字符串，Rust按字段serde(default)、校验并持久化；旧v2和旧备份缺值为空，v1不猜测拆分旧场景造型。sharedFields贯通新建/归一化/搜索/阅读编辑与PNG。类型、前端构建和macOS Tauri release通过；26项策划Node测试通过，其中独立审查复跑内容/导出19项；12项Rust策划定点通过，含旧文档、备份兼容、重开及非法内容原子拒绝。最终资源为index-x56Rwpk-.js / index-utuJmJe4.css。

Avenil复用隔离release实例app.foliune.scene-review，71张测试摄影和两份既有策划。主代理实际填写整组妆造、道具、器材并保存；已有场景补充全选删除后，textarea持续挂载且焦点保持，再原文重填。审查阶段发现的实时trim过滤导致清空卸载P2已按每次编辑资格集合修复，源码及原生操作确认关闭。清空前尝试selectText工具未匹配textarea，改用键盘全选删除，未将工具错误视为产品缺陷。未增加新场景的空造型字段。

原生1320×880宽窗和921×928窄窗检查前部整组准备、单图/三图卡片、相邻场景边界及窄窗编辑；独立验收查看真实截图，确认单层浅底细边卡片可辨、三个区域标题明确、照片完整、镜头首列与拍法起点稳定、文字可读，无已证实遮挡或层级问题。卡片边界与层级验收不能替代用户审美认可。新增字段全空隐藏已做源码及测试核对，本轮未另做原生清空全部字段演示。

Avenil重启后，实际按器材内容“存储卡”检索仅命中目标策划，打开读取三项准备和旧场景资料均恢复。只读核对71份原件SHA256、71条相簿关系与基线一致；两份策划的原JSON字段/场景/镜头/引用/意图/ID保持，目标仅新增三项全案准备及更新时间；SQLite完整性ok、外键问题0。备份恢复由Rust兼容测试验证，本轮未通过原生备份对话框重做。
