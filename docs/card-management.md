# 相簿与画册卡片管理

## 场景与方案（2026-11-01）

用户明确统一卡片交互：单击打开内容，右键进行管理；移除常驻管理按钮，保留新建入口与键盘菜单支持，其他样式不变。

照片与封面优先，沿用当前字体、卡片、背景和布局。相簿卡片菜单提供相簿信息（修改名称、简介与容量）和删除；画册卡片菜单提供重命名和删除。删除仍先显示现有风险确认，不直接执行。卡片获得焦点后 Shift+F10 或菜单键打开同一菜单，取消恢复焦点。右键不打开内容、不改变照片选择。未归入相簿是虚拟集合，不提供重命名与删除。

复用照片原生菜单的资源、互斥和陈旧动作保护，不另做一套视觉菜单。管理入口不得使用当前打开的相簿或其他卡片代替被右键对象，信息统计须对应实际对象；忙碌、对象消失、切换页面或卸载后不得执行陈旧操作。

## 验收范围

- 相簿与画册：单击打开、右键菜单、键盘菜单、取消与焦点、管理弹窗目标、删除确认取消。
- 相簿：从首页打开信息时统计正确，不误用当前相簿 ID；虚拟集合不显示破坏性操作。
- 画册：管理图标移除，封面/元数据布局与新建入口保留。
- 照片菜单继续可用，管理菜单与照片菜单共享原生跟踪互斥。
- 使用独立验收图库，原生检查不删除或改写摄影材料。类型/构建与交互、设计验收分别记录。

## 实施范围

复用并提取 `use-context-menu.ts` 原生菜单核心，照片通过原接口薄包装继续使用。三类菜单共用跟踪互斥，菜单项 ID 按 photo/album/book 隔离，保留代次、目标校验、资源释放和取消焦点恢复。

相簿首页卡片绑定右键与键盘菜单；信息表单统计改为目标相簿 ID。实体相簿内部更多菜单不再重复提供管理入口，仍保留内容级工具；虚拟集合信息查看保留。信息表单删除按钮移除，删除统一从卡片右键进入确认。

画册整张卡片（包含底部元数据）单击打开、右键管理，封面按钮保留唯一键盘焦点入口；移除常驻管理图标，底部保留原行高度与元数据样式。没有改动封面、照片、字体、导航、背景或画册纸张样式。
