# 应用内镜头文字层级

## 范围与意图

镜头清单用于现场快速阅读拍法与构图信息。本轮只整理应用内镜头条目的字号、字重与行高，让名称提供轻量定位，正文稳定易读，标签和编号安静退后，延续现有中性深色与现代系统字体。场景参考照片仍是视觉主体。

保留当前场景卡片、64px 标签列、860px 阅读宽度和基本间距；不改文案、数据、交互与 PNG 导出，也不新增字体族或全局变量。

## 实施方案

- 镜头名称：14px、450 字重；阅读与编辑状态一致。
- 镜头正文：关键拍法、详情值及旧参考要点统一 13px、400 字重、1.75 行高；参考要点保留现有次要颜色。
- 标签、编号和优先级：统一 12px、400 字重。标签保留次要颜色，优先级保留现有轻边徽记。
- 镜头范围显式覆盖通用标题与表单标签字重，避免标签被标题或全局 label 规则加重。编辑正文沿用相同正文尺度。
- 阅读态编号顶部偏移由 4px 收至 2px，适应缩小后的名称行高；编辑态使用 8px，补偿名称输入框的 6px 顶部内距。其他布局与间距保持。

## 验收依据

静态核对选择器只影响应用内镜头区，确认阅读和编辑状态的文字层级一致，并运行 TypeScript 类型检查。真实应用中检查宽窄窗口、长名称、多行拍法、详情标签、旧参考要点及编辑状态；以主次清楚、字重连贯、无截断和基线协调为通过依据。

类型检查不代表设计验收通过，原生窗口的实际观感由独立验收记录。

## 本轮验证记录

开发者类型检查通过，主代理macOS release构建通过，并以Avenil重启 `Foliune 场景排版验收`。本轮仅修改应用内镜头CSS与此方案；`PlanShots.tsx`、`PlanParts.tsx`、PNG内容模型及渲染模块SHA与本轮基线一致，证据在 `.build/verification/planning-shot-typography/`。

首次原生检查被Mac锁屏阻止，用户回复“继续”后已恢复检查。主代理在Avenil管理的同一macOS release隔离实例中，以真实摄影样本检查1320×880宽窗、949×1039窄窗、两场景及编辑状态。名称较旧版更轻，拍法、详情及旧参考正文尺度一致，标签与编号退后但可读，编号与名称基线协调；第一场详情齐全及第二场缺省详情均无截断、遮挡或空字段占位，编辑字号同步且操作可达。只进入并取消编辑，未修改或保存任何内容。截图wide/narrow/narrow-edit/narrow-tail及read/edit AX位于本轮证据目录。shot-detail.png仅为实际宽窗截图的裁图。

独立静态审查通过并独立复跑类型检查通过：确认镜头标签字重能覆盖通用标题和label规则，读写正文尺度一致，选择器不影响场景参数、照片、全案标题及PNG。原生证据已补齐，独立视觉复核结果见下。

完整性核对：两份策划全行含时间戳、71原件SHA与71相簿关系不变，SQLite ok、外键问题0。本轮通过统一文字尺度、降低镜头名称重量使照片与文字主次更协调；没有新动效，未新增Windows、极长内容或完整保存重开的实测。PNG代码保持，未重新导出。

独立视觉复核发现编辑态编号比输入文字偏高，已仅将编辑态编号顶部偏移补偿为8px，读态维持2px。重新release构建并以Avenil重启后，主代理复验 `edit-final.png`，编号与输入文字对齐已改善，未见遮挡；取消编辑恢复阅读，无数据修改。其它宽窄阅读结论保持。

独立审查者复核最终编辑截图、宽窄阅读及尾段证据后确认无需返修：编辑编号偏高问题关闭，文字层级及焦点、优先级和排序删除控件正常。此结论限当前真实样本，不外推至极长新内容或完整编辑保存；原生操作由主代理执行。
