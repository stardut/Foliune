# 相簿选片后的模拟排版

> 后续用户已明确仅临时预览、不保存或提供草稿。相簿选片入口保留，当前交互与字段以 [仅模拟预览](social-preview-only.md) 为准；下文草稿与保存的实现、测试为历史记录。

## 2026-11-02 用户修订

排版不再占独立导航入口，用户在相簿选择照片后使用「模拟排版」。此前模特与社交排版验收中的五入口截图为历史记录，以本次修订为准。

场景与视觉：沿用相簿已有选择栏，在出现选择后提供短操作「模拟排版」；不向照片叠加常驻工具，不另建导航分区。进入排版直接带入已选照片，照片范围及顺序与相簿业务顺序一致。退出回到原相簿及选片上下文。已有草稿通过相簿更多菜单「排版草稿」访问。

边界：不调整平台预览、持久化结构或备份规则，不给历史草稿增加未经用户要求的相簿归属。预填选片不自动保存；未保存退出、工作区切换及原生关闭继续受保护，保存期间禁止跳转。排版内的 Escape 不清空图库选择。

验收目标：顶栏四入口；收藏／作品相簿多选进入；选片范围与顺序；原相簿、选择、页码与滚动恢复；新草稿保存与旧草稿重开；未保存取消／放弃及原生关闭；宽窄窗工具条和上下文入口可达。

## 实现与验证

本轮仅修改 App、图库工作区、相簿标题、照片选择栏及排版工作区的前端状态与入口，不改 Rust、数据库或平台预览算法。独立代码审查未发现确定缺陷。

`pnpm typecheck`、`pnpm build`、macOS release 独立验收包和标准 `Foliune.app` 构建通过。构建保留原有静态／动态混合导入及大于 500 kB 的分块提示；后端未改，没有重复 Rust 全量测试。

在 Avenil「Foliune 模特排版验收」托管的独立测试库（65 张真实混合比例摄影）操作，未触碰用户原件或生产图库。窗口约 1320×880 与 922×720，实际验证：

- 顶栏只有收藏、作品、画册、模特；相簿三张已选照片后可点击「模拟排版」。先点 65 再点 01、64，带入排版仍按相簿顺序为 01、65、64，显示未保存。
- 进入前只读核对已有 1 份草稿；预填和放弃均未新增草稿。排版中按 Escape 后退出放弃，原相簿仍保持三张选中；窄窗中段前后截图的照片边界和滚动位置一致。
- 显式保存「相簿选片入口验收」后显示已保存，保存按钮禁用，直接返回原相簿，不再出现未保存确认。
- 相簿更多菜单打开「排版草稿」，列表含新三图草稿与原六图 Instagram 主页草稿，没有空白新建入口。旧草稿重开保留平台、六张照片和原文案，返回列表再返回相簿层级正确。
- 到第 2 页再选一张，跨页四图全部带入。未保存预填直接触发系统关闭确认，继续编辑后仍四张；放弃后恢复第 2/2 页及四张选择。
- 宽窄窗选择栏的计数、加入画册、模拟排版、更多与取消都可达，沿用现有材质和照片优先布局，没有向照片增加常驻工具。

只读核对：旧草稿 ID、名称、平台保持；新草稿照片为 01／65／64；仍 65 张照片与 67 个相簿关系，外键异常 0。未保存的跨页四图未写入。证据在 `.build/verification/album-social-entry/`：`data-before.json`、`data-after.json`、`source-final.json`、构建日志及九张有效原生截图。

独立代理审查代码及截图，确认中段滚动恢复、第二页返回、四入口、草稿层级和宽窄窗主操作可达性，未发现功能或设计返修项。本轮以场景内操作减少导航占用，保持统一控件、照片主次和材质语言，满足「高级」与「设计感和质感」在本次小范围调整中的实施依据。

限制：实际点击、键盘、保存和原生关闭由主代理操作；独立代理未观看录屏，不据此声明完整动效流畅度通过。原生实测以收藏相簿为主，作品相簿按共用实现代码审查；未新增作品库测试数据，也未重测外部平台、Windows、备份恢复或不同桌面背景。早期极端滚动的瞬态空白截图 `selection-narrow-tail-before.png` 未纳入通过证据。
