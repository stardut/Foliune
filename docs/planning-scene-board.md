# 场景拍摄板

## 本轮目标与依据

2026-11-03 用户否定上一轮策划页面的零散编排及展开收起。阅读时，应在同一个场景中看到参考图、镜头清单、光影和镜头焦段；编辑沿用同一板式，不再把字段藏在详情中。此前文档关于按需展开的约定以本轮用户要求为准。背景、导航及数据层边界保持现状。

## 可检查方案

- 全案头部保留标题、创作构想与四项拍摄信息，以紧凑排版替代“全案概览→标题→全案信息”的重复层级。共同视觉及已有总体参考直接显示，不设置折叠入口。
- 每场景是一块完整拍摄板，以场景间距和一条极弱外部边界确定归属，不增加嵌套卡片。标题行只保留序号、名称及编辑操作，拍摄要点紧随其后。
- 参考影像带位于标题要点之后，1–3 张均完整比例显示，视觉高度约 200px；参考意图与所属图片相邻。零图草稿允许，历史超额图全部保留并提示整理。
- 下半部宽窗采用约 2:1 两栏：左侧镜头清单，右侧“标签＋值”场景参数。参数以光影、镜头焦段优先，其后场地、造型与道具、情绪、时间，直接显示。
- 镜头采用序号有序条目，名称与优先级同一行；关键拍法作为正文，景别构图、姿态、特殊光线、情绪以紧凑标签行直接显示。历史镜头参考留在对应条目，以小影像组显示，不搬到场景。
- 编辑保留上述结构，单行起步且随内容增高的输入减少表单堆叠；字段及控制保留可辨识边界和焦点。已有自由清单直接显示，空清单用“补充清单”入口新增。移除/排序/保存与未保存保护不变。
- 窄窗下两栏转为连续单列，镜头与参数仍属于同一拍摄板；标题、工具及图片自然换行，文字不截断。长图采用标题要点→图→镜头清单→场景参数的手机阅读顺序，完整保留历史字段及图片。

## 验收依据

结构检查要求策划目录内无 `<details>` / `<summary>`，所有已填字段直接可见，阅读与编辑中场景归属明确，历史参考ID及绑定不变。类型检查、前端构建及策划内容/导出/断行 Node 测试由实现者执行；主代理独立验收真实应用、真实横竖方摄影、宽窄窗首中尾、键盘及保存路径。构建通过不等于视觉通过，不凭实现者自评声称“高级”。

本轮以摄影占据场景上部主视觉、克制的编号和参数对齐建立设计感；质感依靠连续背景、统一排版和细控件，不新增装饰材质或全局样式。原生设计结果及未测范围交主代理补充。

## 实现与自动验证

实现涉及 PlanDocument、PlanParts、PlanShots、PlanFields、PlanPhotos 与局部 planning.css，独立 PNG 仅调整内容排序，不改渲染算法。新增镜头不铺添加参考入口；有历史镜头图时保留图组与调整入口。阅读与编辑均在 760px 以下转单列，不以编辑模式改变宽窗场景归属。单图参考左对齐并完整显示，返修后图文改为上下相邻、figure最多440px；图片高度不放大，消除意图游离到右列的问题。
