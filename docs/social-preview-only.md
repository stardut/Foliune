# 相簿中的临时社交预览

## 2026-11-02 用户最新修订

仅模拟预览，不需要保存或草稿；头像与昵称固定，按平台适配文字结构。此约定取代前两轮排版草稿及入口文档中保存、草稿列表和离开确认的产品范围。

## 场景与方案

相簿多选后点击「模拟排版」，照片直接带入临时界面。保留选片、排序、平台切换和翻页预览，返回恢复原相簿上下文。模拟过程只使用当前组件内存，离开直接结束，不弹未保存确认。模特、照片详情及画册各自的未保存保护继续成立。

固定使用本地可读取的头像图像和「Foliune 摄影」昵称，不提供身份输入，不请求外部头像资源。工具沿用现有深色控件，平台内部保持局部浅色画布；减少表单与状态文案，让照片及实际效果承担主要视觉。

后续顶部精简按用户截图反馈实施：去掉可见「模拟排版」大标题和相簿名，返回仅保留轻量箭头，带「返回相簿」提示与可访问名称；平台、文案和预览整体上移。局部间距沿用现有控件体系，不增加底板或分隔线，不调整平台内部内容。section 仍保留程序可识别的名称。

| 平台 | 文案输入与展示 |
| --- | --- |
| 微信朋友圈 | 单个文案框，普通文字，标题与正文不分开。 |
| 小红书 | 标题与正文分开输入和预览。 |
| Instagram 帖子 | 单个配文框，不显示小红书标题。 |

切换平台保留正文和小红书标题，其他平台隐藏标题，不自动拆分或合并用户文字。模拟数量限制按当前应用规则处理，超限保留全部选片，明确说明只预览前 N 张，避免把超出平台数量的画面当作正常结果。

平台选择按用户后续要求改为朋友圈、小红书、Instagram 三项单行平铺原生单选，直接可见并支持键盘方向键。表单焦点沿已有边框显示灰蓝细线，不再使用粗白外圈；全软件审计和代表页验证见 [控件焦点与平台单选](form-focus-platform.md)。

## 数据边界与验收

删除前端草稿入口及调用链，预览不读取或写入草稿，也不写 localStorage。旧版已产生的历史数据本轮不做破坏性删除；其存在不表示产品继续提供草稿功能。

验证相簿选片进入、三平台文字结构、固定头像实际加载与昵称、平台切换保留文案但不串标题、超限显示、无保存／草稿／身份输入、直接返回与再进清空临时内容、跨页选择及滚动保留。分别记录类型／构建、原生操作和独立截图审查结果；仅本轮有变更的路径复验。

## 实现与实际验证

`SocialWorkspace` 化简为纯 `useState` 模拟，移除前端 `SocialEditor`、`social-api`、草稿持久化类型和入口。App／图库不再接收模拟排版 dirty/busy，照片详情、画册、模特及重新定位的原有保护保留。固定头像复用仓库自有 `src-tauri/icons/128x128.png`，由 Vite 打包为本地图片，并配有替代文本。

`pnpm typecheck`、`pnpm build`、macOS release 验收包与标准 `Foliune.app` 构建均通过；构建仍有既有混合导入和大分块提示。后端未改，未重复 Rust 全量测试。

原生验收在 macOS 15.0.1 的 Avenil「Foliune 模特排版验收」独立实例中进行，使用原有 65 张真实摄影测试库，宽窗约 1320×880，窄窗约 922×720。实际操作结果：

- 从相簿带入三图，表单没有草稿名、身份填写、保存／删除操作或未保存状态。朋友圈只有一个文案框，本地 F 图像头像实际加载，昵称为「Foliune 摄影」。
- 输入两行文案后切小红书，正文保留，另输入「只在小红书显示的标题」；切 Instagram 帖子时只显示配文，原文保留且专属标题不显示，翻页到 2/3。
- Instagram 主页显示简介和三列网格，没有小红书标题；固定头像与昵称在主页实际可见。
- 临时选十张后切朋友圈，提示「预览前 9 张，已选 10 张」，右侧实际只显示九张；左侧完整十图与顺序仍保留。
- 再切小红书，专属标题仍在输入框和预览中，正文保留。模拟内 Escape 不清原相簿选择；直接返回没有确认，原相簿仍三张选中，临时十图不修改原选择。
- 相簿更多菜单没有「排版草稿」。重新选片再进入，先前正文与标题均未恢复。重新填写文案后点击原生关闭，Avenil 状态为 exited，没有保存确认。
- 最终只读核对五张相关表的数据 SHA-256 与测试前完全相等：照片65、相簿关系67、模特1、历史草稿2及历史引用9均未变化，外键异常0。历史行未被新增、覆盖或删除。

独立代理审查最终代码及七张本轮原生截图，未发现需返修的功能或设计缺陷。减少持久化表单和状态文字后，照片与平台效果更突出；深色工具与浅色预览隔离、固定头像清楚、宽窄窗操作可达，符合本轮「高级」与「设计感和质感」的具体实施依据。

证据在 `.build/verification/social-preview-only/`：`moments-wide.png`、`xiaohongshu-wide.png`、`instagram-post-wide.png`、`instagram-grid-wide.png`、`instagram-grid-narrow.png`、`moments-overlimit-narrow.png`、`xiaohongshu-caption-narrow.png`；另有关闭前的 `ephemeral-state.txt`、前后数据摘要、源码摘要与构建日志。

限制：动态点击、平台切换、返回、再进入与关闭由主代理操作；独立审查为代码及静态截图，没有观看动效录屏。没有重新构造缺图或外部服务异常，没有重测 Windows、正式分发或完整画册／备份流程。平台数量和画布继续为应用内模拟，不声称匹配各版本客户端的全部规则。

## 2026-11-02 缩略图网格与预览适屏方案

用户场景：一边查看社交平台效果，一边通过照片本身调整顺序。左侧以至少三列的缩略图网格取代单列文件行，宽栏可增加列数；不常驻显示名称，保留轻量序号、按需移除及可访问名称。直接拖动缩略图，同排和跨排均按阅读顺序插入；跟手浮层与占位沿用现有中性深色材质，不添加新的工具面板。完整构图的缩略图帮助摄影内容辨认。

右侧根据实际可用视区和平台画布尺寸整体等比适配，常见朋友圈九图、两种多图帖子配短文尽量完整显示，左侧多图不推走右侧预览。保留平台结构和照片比例；超长文案保留完整内容，允许受控局部滚动，不以裁掉文字或无限缩小换取无滚动。保持三平台单行、固定身份、仅内存模拟和直接返回。
