# 统一页面操作提示

2026-11-03，按用户要求，将页面操作结果统一为右上角悬浮提示并自动消失。

## 场景与方案

相簿增删、照片操作、画册保存与导出、模特档案保存、设置与备份等操作结束时，给出紧凑提示，不挤压照片墙或工作区。复用中性深色 `--floating`、细边缘、柔和阴影与现有字体；照片仍为视觉主体，不增加解释文案或装饰色块。

采用共享 ToastProvider 与 beUI `animated-toast-stack` 公共 MIT 源的精简适配：成功和普通提示 3 秒，操作失败 6 秒；错误同时用图标和文字表达。一般提示保留轻量关闭按钮，拼图「保存成功」遵守既有产品约定，不显示关闭、查看或相簿名。长路径及错误允许换行和复制。不同提示独立计时，相同提示重新计时，不借用旧定时器关闭新提示。

浮层在右上角窗口安全区域下方，与页面滚动分离。通过 manual popover 进入浏览器 top layer，并按共享模态栈记录的实际 showModal 顺序调整 DOM 宿主（不按 DOM 排序猜测顶层），避免被原生模态框遮挡或成为 inert 区域。展示不设 autofocus，不改变当前焦点。默认可见，仅用短距离位移进入；到时或关闭直接卸载，不依赖退出动画；减少动态效果时无动画。

## 范围与状态

- App 普通反馈、设置成功反馈、画册编辑结果、模特保存结果、拼图成功提示使用统一浮层。
- 加载失败及其恢复入口、字段校验、导入失败明细、未保存与处理状态继续保留在任务上下文，避免错误详情随计时丢失。
- 不改 IPC、持久化、照片、纸张与独立 HTML 导出样式。

## 验收依据

类型检查与生产构建应通过。独立验收需检查：真实应用内相簿操作后照片墙位置不变；提示右上角出现并按时消失；重复与连续反馈不会提前关闭；模态框内产生反馈仍可见；关闭不影响编辑焦点；长文可读、窄窗不溢出；拼图提示仍无关闭入口；减少动态效果时直接呈现。静态检查和浏览器检查不代替原生 WebView 动态与摄影内容验收。

## 实施验证

已接入全局反馈、设置、画册编辑、模特保存与拼图成功提示；类型检查与生产构建已通过。独立审查发现 DOM 顺序不能表示模态层级，已改为共享模态栈显式记录实际 showModal 顺序，覆盖通用 Modal、画册阅读、照片欣赏及大图查看。原生动态及设计验收由主代理独立执行，本实现记录不代表已通过。

最低 macOS 11 支持的旧 WebView 不提供 Popover API，故明确检测该能力；现代 WebView 用窗口右上角 top-layer 浮层，旧 WebView 无模态框时仍为窗口右上角，模态框内则使用其可见区域的右侧提示，防止 backdrop-filter 固定包含块与 overflow 裁切造成不可见。此限制服务于已经声明支持的平台，不是为未来平台增加兼容。鼠标关闭阻止指针默认聚焦，键盘关闭及聚焦期间自动移除将焦点还给此前有效控件。

2026-11-03，独立审查修复模态打开顺序、StrictMode 旧 close 事件、旧 WebView API 检测及关闭焦点后，无新增阻塞问题。实际 hook 源码编译后的虚拟时钟验证覆盖同文案重新计时、同毫秒连续触发、不同文案独立到期、成功 3 秒/失败 6 秒、手动关闭及卸载清理；模态栈脚本覆盖打开顺序、逐层恢复及 StrictMode 事件队列，均通过。

## 右下角与轻量样式修订

2026-11-03，用户明确要求改到右下角并优化当前外观。本节取代前文右上角位置与首轮样式判断，历史截图仅保留为对照。

提示停靠窗口右侧及底部各约 24px，连续提示从底向上堆叠；旧 WebView 的模态宿主回退同步改到其右下角。不改共享 Provider、计时、模态栈、焦点和关闭规则。

沿用现有中性深色浮层，将内边距收紧为 9×11px、圆角 10px，降低边缘对比，以一层短柔影承托，成功使用轻量勾号，错误保留语义图标。正文与图标按首行对齐，关闭按钮保留 26px 点击区域，不增加文案或装饰色。长文继续换行、可复制和滚动；滚动容器四周保留 24px 阴影空间，使浮层边缘不再被 overflow 直接切断。默认可见、直接卸载和减少动态效果支持保持。

验收聚焦真实应用右下角停靠、照片优先、浮层边缘与对齐、连续提示及长文阅读；生产构建仅证明可构建，最终视觉由主代理独立检查。
