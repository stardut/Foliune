# 展览拼贴布局

本文说明图库“展览”视图的当前实现。2026-10-29 至 2026-10-30 的切片树拼贴已替代早期固定三张、面积权重与底线对齐方案；旧方案及其截图不再代表当前布局。相簿入口和头部交互以当前界面为准，画册排版独立于此布局。

## 实现与职责

- [`exhibition-layout.ts`](../apps/desktop/src/features/exhibition-layout.ts) 是独立几何计算模块，输入照片尺寸、画布可用宽度和窗口高度，输出连续拼贴块及照片坐标。
- [`PhotoCanvas.tsx`](../apps/desktop/src/features/PhotoCanvas.tsx) 以统一虚拟画布渲染全部照片与作品分组，负责选择、菜单、大图入口和键盘跨虚拟边界；[`use-photo-wall.ts`](../apps/desktop/src/features/use-photo-wall.ts) 管理测量、Worker结果、缓存与视口范围；[`photo-wall-layout.ts`](../apps/desktop/src/features/photo-wall-layout.ts) 生成全量稳定坐标。
- [`PhotoReview.tsx`](../apps/desktop/src/features/PhotoReview.tsx) 提供图库的完整比例大图查看；[`library-photo-order.ts`](../apps/desktop/src/features/library-photo-order.ts) 对作品全量结果生成分组，墙面和预览复用同一序列，不参与拼贴几何。
- [`library.css`](../apps/desktop/src/features/library.css) 定义展览满宽布局、细缝和上下文浮层。规则限定于图库工作区的展览视图，总览和画册纸张使用各自布局。

## 原比例与连续覆盖

多张照片的每个拼贴块由横向或纵向二分的切片树组成。叶节点使用照片宽高比；子树包含缝隙后的尺寸满足 `width = a × height + b`，横向和纵向拼接分别合并这条关系，再按整块宽度求高度与坐标。块内照片连续覆盖矩形，只留统一细缝，不通过裁切、拉伸或留洞凑版式。

画布只有一张照片时采用浏览尺寸：宽度不超过可用宽度及 480px，高度不超过 360px 和窗口高度的一半，按原比例适配这两个边界。照片左侧与相簿内容轴对齐，不使用多图展览的满幅负边距；不新增底板、描边或说明，保留单击预览、选择及菜单路径。此规则按每个画布的输入数量判断；多图输入的分块与尾数仍沿用拼贴算法。

块内缝由 `EXHIBITION_GAP = 4` 参与几何计算，块间 CSS 间距也为 4px。照片容器尺寸依原比例计算，图片使用 `object-fit: contain`，保留完整构图。选择框和图注叠加在照片内部，不扩大几何区域。

算法只组合连续的照片区间，不排列或调换照片。窗口变化可改变二分方向和块边界，输入业务顺序、DOM 顺序及每张照片恰好出现一次保持不变；保序不要求所有照片排列成等高横行。

## 分块与评分

每块候选包含连续 1–6 张照片，枚举其横向、纵向切片树，并缓存各区间候选。六张区间最多有 1344 棵树，不枚举照片顺序。动态规划从序列尾部向前比较“当前块评分 + 剩余序列评分”，选择整段输入的分块，因此少量照片与不足六张的尾数也是完整输入。

评分同时考虑照片面积、过短边、过高照片、占宽过大的照片及块高，并偏好大图跨越相邻堆叠图的组合，减少连续等高行。评分是软偏好，不保证固定主图、固定面积比例或每块同样高；窗口高度参与评分，几何仍由原始比例决定。

空输入或非正、非有限的画布宽度返回空布局；无效照片尺寸在计算中按方形比例处理。候选产生非正或非有限尺寸时会被拒绝；有效输入若无法选出布局会明确抛错。

多图拼贴的原比例、满宽和完整构图也有数学边界：单张尾块中的竖图铺满宽度时必然很高，极端宽图可能很矮；少量照片或极端比例不一定同时满足评分偏好的最短边和高度。实现保留比例与覆盖，不把软评分当作所有输入都能达到的视觉下限。只有一张照片的画布使用上述明确尺寸边界，不参与满宽拼贴评分。

## 交互与计算成本

静止时照片为主体，不叠加编号、文件名和工具带。浏览模式单击预览；通过照片右键或Shift+F10/菜单键选择后，其他照片单击增减选择。未选照片的菜单只针对该照片，已选照片的批量操作使用完整当前结果的已选集合，菜单标明数量。键盘焦点保留细内框；虚拟化保留焦点单位，Tab和Shift+Tab可跨越未挂载边界连续访问照片及缺图修复入口。照片节点默认可见，不依赖Motion或动画结束完成显示；清空选择直接卸载选择栏。

相簿和搜索不再分页。作品按完整结果一次分组，所有分组标题、展览块或总览行放入一张稳定总高度的画布；大图及批量操作直接复用墙面的完整序列。选择与原件关系不变，大图只查看，不改变选择。拼图及模拟排版返回时，在画布测量与完整布局就绪后恢复一次原滚动位置；切换相簿、状态、搜索或作品分组会取消旧恢复并置顶。

展览几何由独立 Web Worker 沿用切片树算法计算，并报告计算和 Worker 加载失败。长分组先排 32 张，其余照片按连续顺序均衡分段，每段最多 128 张。每段保留切片树评分、原比例和完整构图，段间沿用 4px 细缝。Worker 按批次追加坐标，已显示的位置保持稳定，最终结果用于缓存及恢复滚动位置。短分组沿用整组求解。调整窗口时保留旧墙，完成新布局后切换，避免暂时缩短画布把深处滚动位置截回。缓存最近 3 份完整布局，照片 ID、尺寸、分组或视口尺寸变动时重算。总览仍用固定列宽直接生成行坐标。

滚动沿用系统行为，每帧至多检查一次二分可见范围；只有范围改变才更新React，仅挂载视口上下各至少900px或1.5个视口的预备区域，另保留焦点单位。照片节点使用memo，选中集合使用Set；内容签名与布局键缓存，避免每次滚动重新复制全库签名。新挂载图片立即请求并异步解码；真正等待读取时仅轻微透明度交接，缓存已完成的图片在首帧前清除等待状态。照片始终可见，减少动态效果时无图片过渡，读取提示保留延迟但不淡入。此结构限制DOM挂载量，不等于已完成任意规模图库的release性能验收。方案及本轮验证见[相簿连续虚拟滚动](album-virtual-scroll.md)。

## 已执行验证与边界

### 2026-11-03 单图浏览尺寸修正

场景：相簿仅有一张照片时，进入照片墙仍按整幅画布铺宽，竖图和方图显得过大。此轮以克制浏览尺寸与内容轴对齐恢复观看距离，照片继续作为主角；不增加底板、说明或新操作，既有中性连续背景与控件样式保持一致。多图照片墙和大图预览独立，不改其尺寸策略。

已执行 `node --test apps/desktop/tests/exhibition-layout.test.mjs`，4项通过：100组单图覆盖横、竖、方、极宽、极竖及宽窄/矮窗口，检查明确尺寸边界、原比例、左上对齐和块高；15组多图检查满宽、业务顺序、每图一次、不重叠及原比例，并保留空输入/无效宽度检查。`pnpm typecheck` 通过。macOS release构建通过。独立审查复跑4项测试，并将48组多图输入与修改前输出比较，完全一致，无已证实P1/P2。

主代理通过Avenil重启隔离实例 `app.foliune.scene-review`，在1320×880和952×880逻辑窗口检查真实竖图3000×4000、方图1280×1280，以及搜索唯一结果的横图2500×1667：照片首屏完整，宽窗不继续放大，左边缘与页面内容轴协调。实际单击预览、Esc返回、右键/Shift+F10菜单、选择反馈与取消选择可用；菜单后AX曾延迟更新，后续完整AX和截图已确认选择栏出现及清选卸载。另在窄窗检查65张相簿第一页首段、中段、末尾。独立审查者复核竖方宽窄、选择与预览截图，无构图裁切或遮挡。本轮以观看尺度、完整构图和留白落实设计质感，不代表用户最终审美认可。

证据在 `.build/verification/single-photo/`，资源 `index-BXh9kEKk.js`。图库所有表行与71张原件SHA均与基线一致，SQLite完整性ok、外键问题0。单图规则按每个画布输入数量生效，包含搜索单结果、作品单张分段和分页末页单张；多图块内单张尾块不变。Windows、异常图片、全部键盘路径及完整动效未新增实测；极端比例和矮窗仅由几何测试覆盖。

### 既有拼贴验证

2026-10-29 至 2026-10-30 的独立审查覆盖上述三个源文件及拼接方程、尺寸拒绝、1–6 张分块、保序和监听回收。独立几何检查使用真实素材尺寸，在 896/1296px 可用宽度下验证 1/2/4/5/7/11/36 张共 14 组输出，叶节点比例误差不超过 `1e-7`；实现者另执行了 288 组几何断言，两者是不同来源的证据。

真实 macOS Tauri 窗口使用独立恢复图库，经系统文件选择器导入 36 张真实摄影；在 1320×880 与 920×880 窗口的首屏、中段、尾部检查拼贴，并实际缩放、滚动、选择、键盘进入详情、关闭详情、进入欣赏及切换总览。该样本未见内部空洞、拉伸或裁切，照片有大小和横竖变化，细缝约 4px，选择与浮层未改变布局。

少量照片、尾数及合成极端比例只有几何检查，未逐种排列做原生操作。Node 单次计算耗时和本机 release 导入观察只属于当时机器与样本，不能推导所有图库的性能；Windows、真实跨页操作及大图库压力仍未在本轮验收。

完整本地记录为 `.build/verification/mosaic/review-verification.md`，截图及数据证据位于同目录。它们是忽略的验收产物，可能不随检出提供，也不是运行或理解实现的依赖。通用原生验收方法和其他主流程覆盖见[桌面验收](desktop-verification.md)；实现细节以本文链接的当前代码为准。
