# 工程边界

## 作品目录与外部原件

作品目录的来源、相簿映射、外部照片和忽略记录属于当前图库。发现阶段只生成待确认批次。确认后按相簿进入后台队列，在图库锁外读取外部原件及准备缩略图。每本相簿独立通过事务提交照片索引及相簿关系。任务提交事件携带图库标识及该相簿新增的数据，界面可保留同时发生的其他编辑。照片 ID 保持稳定，外部路径由来源根和相对文件名解析。缩略图存入图库缓存，原件从绑定目录只读访问。删除相簿保留外部照片记录及已有画册引用，并保留来源的排除记录。

外部原件通过专用图像协议按当前图库内的照片 ID 读取。目录离线或文件缺失只改变可用状态。仅图库资料备份保留作品目录的来源关系和索引，恢复后的来源路径需要用户重新授权。交互及验收见[作品目录绑定](work-directory.md)。

已确认的同步任务及文件清单随当前图库保存，准备进度留在当前进程。相簿索引和任务移除在同一事务中提交。重新打开图库时恢复待同步任务，外部目录上线后开始准备。备份包排除未完成任务，避免将旧机器上的同步授权带入恢复后的图库。

macOS 的作品目录同步按文件内容识别 JPEG，从已校验的文件句柄读取有界字节，用 Image I/O 创建完整尺寸的图像源。Core Graphics 在绘制时完成解码、EXIF 旋正、等比缩放与 sRGB 转换，输出最长边不超过 960 px 的 JPEG 缓存。索引仍记录旋正后的原图宽高。SHA-256、文件状态复核、暂存和相簿事务沿用同步流程。PNG、WebP、手动导入及替换原件使用原有解码路径。

## 照片来源与链接候选

`PhotoSourceDialog` / `PhotoSourceGrid` / `use-photo-source-import` 提供图库、本地、链接的共用选片与候选生命周期。`photo-import-api.ts` 封装 `prepare_link_import` / `cancel_link_import`，用请求专属的 Tauri Channel 接收总数和逐张就绪的候选。准备结果仍为 `CurationDraft`，确认和取消沿用候选提交接口。来源对话框负责候选选择与容量取舍，各业务只接收稳定照片 ID 和提交后的 snapshot。策划与画册新增 snapshot 回流，无需重新挂载编辑工作区。

Rust `link_import.rs` 管理请求标识、启动图库绑定、取消和候选交接；`link_import_input.rs` 约束分享文本、平台路径与短链跳转；`link_import_webview.rs` 创建随机label的独立无痕窗口，拒绝新窗口与非平台导航，只接受带随机nonce的终态回传；网页没有匹配的远程图库IPC能力。`link_import_extract.js` 校验精确目标帖子和完整静态媒体列表，最终回传前不触发主框架诊断导航。`link_import_download.rs` 约束各平台HTTPS CDN、禁重定向、限时限量、后台解码与原字节暂存。LIVE照片仅取静态版本，视频不混作图片。

`link_import_source.rs` 对每张下载图片解码并生成缩略图，保存原字节和规范化帖子来源。原件和缩略图写入当前图库的会话暂存目录后才发布对应候选。整组成功后，`link_import_curation.rs` 将同一批候选交给取舍会话，正式入库仍由 curation 原子提交。取消与暂存文件写入串行，前端忽略过期会话的进度。会话和临时文件排除在备份之外，照片来源仅保留帖子地址。方案与验收见[统一照片来源](photo-source-import.md)。

## 当前桌面路线

当前使用 `apps/desktop` 的 Tauri 2 宿主与 React 19 界面，TypeScript 定义前后端共享的数据契约，Vite、Tailwind CSS 4 和 Motion 负责界面开发。
旧 `apps/macos` SwiftUI 工程保留归档，不参与本路线的构建。没有新增移动端工程。
Tauri 的结构具备跨桌面平台扩展条件，但当前仅验证 macOS，Windows 构建和系统集成仍需目标环境验收。

## 原生操作菜单

`use-context-menu.ts` 保留菜单动作、目标有效性、共享互斥和取消回焦；调用点明确区分鼠标上下文与键盘/更多按钮的定位请求。鼠标路径调用 `popup_context_menu`，键盘和更多按钮沿用 Tauri 定位菜单。`TextContextMenu` 只接管未被业务处理的文本编辑入口，与业务菜单共用互斥；空白、图片及普通网页内容不显示 WebView 默认菜单。

macOS 的 `context_menu.rs` / `context_menu_macos.m` 只在主窗口保存原始右键或 Control+左键 down，不生成或投递输入。下次鼠标/键盘输入、窗口失去键盘焦点、应用失活或消费会清理待用事件；菜单构建耗时本身不使其失效。IPC 从当前 WebView 资源表取已有 Menu，在主线程按窗口与坐标关联原始事件，调用公开 NSMenu context API；关联失败明确反馈，不改走其它 API。Arc<Menu> 与原始 NSEvent 持有到跟踪结束，Promise 此时才完成；关闭窗口移除 local monitor 与通知观察者，弱引用避免 window/observer/monitor 循环。不使用全局方法替换或对象布局转换。其他平台保留 Tauri 原有定位路径。

## 模块职责

- `src/lib/types.ts`：照片、分组、成员关系及操作输入。
- `src/lib/api.ts`：Tauri IPC、系统文件选择、受限 asset URL 转换。非桌面环境明确报错。
- `src/features`、`src/components`：界面及交互，不直接读写数据库或文件系统。
- `src-tauri/src/db.rs`：SQLite 建表、快照读取和持久连接。
- `src-tauri/src/photos.rs`：格式验证、解码、EXIF、管理副本、缩略图和照片信息。
- `src-tauri/src/photo_metadata.rs`：大图信息浮层按照片 ID 从当前图库查询管理副本，锁外只读 EXIF 和文件信息；与导入共用 EXIF 解析入口。拍摄时间与地点继续由图库快照提供。
- `src-tauri/src/groups.rs`：分组 CRUD、容量检查及成员关系。
- `src-tauri/src/airdrop.rs`、`airdrop_macos.m`：按当前图库的相簿和有效成员解析原件，在图库锁外流式复制到独立临时目录。准备完成后复核图库和分享范围，再在主线程交给 AppKit 的隔空投送服务。系统报告完成、取消或失败后清理本次副本。
- `src-tauri/src/curation.rs`：导入、加入、恢复和降上限的候选会话与原子确认。
- `src-tauri/src/books.rs`、`book_layout.rs`、`book_export.rs`：画册文档、编辑保存、初始排版和 HTML 导出。
- `src-tauri/src/ai.rs`、`ai_settings.rs`、`credentials.rs`：官方 API 请求与结果存储、单一接入配置、系统凭据。
- `src-tauri/src/backup.rs`、`backup_restore.rs`：一致性备份、备份校验和单图库增量合并。
- `src-tauri/src/music.rs`：只供当前欣赏会话的管理音频缓存。
- `src-tauri/src/model_profiles.rs`：当前图库的模特档案、有序样片引用及每份档案的可选标签目录，事务校验并保存。删除档案时复用图库引用检查。`tag_options` 为可空JSON列，旧记录null由编辑器采用初始目录，显式空数组保留全部删除结果；启动及备份恢复的init在旧表缺列时增加该列，不清旧数据。
- `src-tauri/src/social.rs`：保留首版历史排版数据的结构与恢复校验。当前模拟界面不再调用草稿接口，本轮不破坏性删除旧数据。
- `src-tauri/src/content_refs.rs`：上述两个模块共用的文案、时间戳和稳定照片引用校验，不承担图库导入与画册排版。
- `src/lib/model-types.ts`、`model-api.ts`：模特档案的类型与 IPC；`social-types.ts` 只定义临时预览输入。`src/features/models`、`src/features/social` 负责界面，`src/components/PhotoPicker.tsx` 提供共用选片对话框；模拟排版仅使用组件内存，不读写草稿或浏览器存储。
- `src-tauri/src/lib.rs`：宿主初始化与 IPC 入口。

Tauri 文件对话框只允许选择公开支持的 JPEG、PNG、WebP。导入端再次按文件内容解码验证，不仅相信扩展名。
asset protocol 仅开放应用数据目录的原件、缩略图、候选图和音频缓存；恢复图库同样只开放对应的图像子目录，不开放数据库、配置或整个用户目录。
照片解码和批量导入使用后台任务，避免占用 WebView 的界面线程。

## 数据规则

SQLite 文件和管理副本位于 Tauri `app_data_dir`，不写入源码目录。
照片使用持久 UUID；分组与照片之间的成员记录有独立的 `active` / `discarded` 状态和排序位置。
同一照片可进入同图库的多个分组。废弃、恢复只修改指定关系。分组容量计算有效成员，恢复和批量加入都要检查容量。
删除相簿、画册、策划或模特档案时，在同一事务内移除对应关系，并仅将本次删除涉及且已无其他引用的照片标记为隐藏。画册只以当前内容判定引用。常规快照排除隐藏记录，保留其 ID 供前端识别迟到的同步结果。备份和恢复使用完整快照，照片记录、文件和隐藏状态一并保留。

批量导入返回成功 ID 与逐项失败原因。本地导入在解码后保存缩略图，用 `local-photo:` 定位器登记绝对源路径，在同一事务中写入照片和可选成员关系。外部原件沿用按照片 ID 读取的图像协议。链接导入保留管理副本，既有管理副本的读取与恢复沿用原有格式。
单项失败回滚该项数据库并清理本次副本，不更改来源文件。数据库错误不回退为空库。
取舍使用独立候选暂存与确认接口。候选新照片只进入该会话的暂存目录；确认时校验保留集合、容量与原分组签名，防止跨会话伪造及并发修改。取消与失败只清理该会话明确持有的目录，未选的新图不进入正式库。批量废弃与恢复也在一个事务中校验并更新，避免部分成功。

## 画册与图库

画册使用稳定的照片 ID 保存选片、章节与页面布局。创建时生成初始排版。编辑、阅读、导出和相簿删除检查都使用当前画册内容，保存时核对当前内容 ID 以拒绝过期写入。历史数据随图库及备份保留，旧画册里的重新排版来源字段仅用于读取兼容。原照片重新定位保持 ID，所有画册引用会采用替换文件，因此必须明确确认替换。

书架通过当前内容的页面阅读顺序派生封面照片，`BookCover` 与 `book-cover-design.ts` 只承担封面完整构图、单色取样与文字对比；取色和照片显示独立，不写入图库或改变原图。界面外壳、画册纸张与 HTML 导出的样式仍隔离，见[摄影出版物书架](book-publication-design.md)。
`Store.root` 是应用根目录，当前图库路径从持久连接取。应用启动时只打开一个图库。升级时沿用旧版最后选中的图库位置，以保留既有的照片路径；旧版位置记录只供启动读取。导入、恢复和重新定位使用当前连接所属目录。

## AI 与凭据

照片分析只由显式用户操作触发，发送已旋正的 960px JPEG 预览，不上传原件、音乐或整个图库。OpenAI Responses 使用 input_image，Claude Messages 使用 base64 image，DeepSeek Chat Completions 使用 image_url。
固定官方端点，不接收任意 URL；请求禁止重定向，连接超时 15 秒、总超时 90 秒，响应限制 4 MiB。HTTP 错误只返回状态与操作提示，不回显可能包含 Key 的提供方错误正文。
系统凭据库以 `app.foliune.desktop.ai` 服务名、提供方为账户保存 Key；SQLite 的 `ai_connection` 通过 `id=1` 单行约束保存唯一接入的提供方、模型及图像能力开关，Key 不进库。IPC设置返回 `connection | null`，不再返回多个提供方配置。替换接入不删除其他提供方凭据；切换提供方必须显式输入Key，同一提供方可留空保留。移除同时删除当前提供方Key。照片与文本请求都核对当前接入和前端携带的提供方，一把连接锁内读取配置及其Key，拒绝无配置和过期提供方调用。分析结果在 photo_analyses 独立表中，不覆盖人工字段。请求前记录图库和图片修订，图片被替换后拒绝把旧结果写到新内容上。

2026-10-29 核验的官方来源：

- [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses)
- [Claude Vision](https://platform.claude.com/docs/en/build-with-claude/vision)
- [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)
- [DeepSeek 模型能力字段](https://api-docs.deepseek.com/api/list-models/)

默认模型仅为可编辑的起点。未知模型由用户明确设置图像能力；未启用时图像分析报错，不静默改用文本结果。

## 备份与恢复

使用 SQLite backup API 取得一致性快照，与缩略图一起写入 ZIP，附 SHA-256 和大小清单。「仅图库资料」保存索引和缩略图，管理副本在归档的数据库中记为待重新定位的原件。「包含全部原片」还读取图库中的管理副本和外部原件，在归档的数据库中将外部原件登记为可恢复的管理副本，移除原目录的同步关系。备份内记录的路径不授予读取权限。系统 Key、音频缓存、未确认会话、库选择文件和旧的未引用图片修订不进入备份。
恢复只接受白名单相对路径，拒绝重复条目、链接、目录穿越、额外文件及校验失败。SQLite 数据库再做完整性、外键、画册布局与图像解码检查，并将新补入照片的管理路径重写到当前图库；文件名提取同时识别 Windows 与 Unix 分隔符。
备份先在独立暂存目录校验，再向当前图库增量写入。已有实体按 ID 保留，同 ID 画册及其版本、模特及其样片、排版和策划及其照片按完整记录保留。相簿可补入符合当前容量的缺失关系，保留已有状态和顺序。新加入的作品目录保留索引但需要重新授权。同路径的当前目录保留授权及同步队列，来源冲突的新照片仅保留索引和缩略图。数据库事务提交前验证引用完整性，失败时撤回本次写入，成功后前端刷新图库并报告无法合入的内容。

暂不提供物理删除照片原件、云端同步或跨设备帐号。系统异常终止可能遗留暂存/缓存；正常取消、失败与退出负责清理明确持有的文件，不扫描删除无关文件。

相簿封面按相簿保存有效成员的照片 ID、两轴相对溢出偏移和缩放倍率。数据库以相簿成员关系约束封面引用。废弃成员保留设置，卡片从有效成员中选图。构图参数随图库备份，增量恢复保留当前同 ID 相簿的设置，新相簿仅在封面成员成功合入时恢复其设置。

取景弹窗读取单张原件。首页先按同一套 3:2 几何显示已有缩略图，靠近视口时经 `read_album_cover` 请求高清裁片。保存封面提交后后台预热。Rust 复用原件读取和旋正逻辑，先在原图像素空间裁切，再缩小并编码成最大 1200×800 的 JPEG。图库内每个相簿保留一份可重建的缓存，按原件修订和取景参数校验，生成后原子写入。生成过程在图库连接锁外单路执行，写入前重新校验当前封面。缓存独立于备份和原件。

模特资料存入当前图库数据库，图片引用 `photos.id`，因此随数据库快照及现有图像文件一起备份。历史排版数据仍随旧库快照保留和校验，当前模拟不新增或更新它们。恢复时检查内容、照片引用及顺序，不因补建表掩盖残缺结构；旧备份不含新模块时补建空表。

## 拼图界面与输出契约

`src/features/collage/collage-layout.ts` 负责有序行分割、网格与长图几何、来源有效像素密度、统一整数矩形、输出尺寸校验、锁比例输出缩放和撤销历史；布局不读写数据库。2400宽参考几何仅用于预览及设计控件，默认成片按所有照片所需倍率的最大值保留来源像素，cover包含zoom后的取景密度；整数化留出边界取整余量。单边32768、总像素160MP的限制只拒绝不支持的输出，不偷偷缩小布局；导出对话框允许用户显式调整并恢复原图尺寸。`CollageWorkspace` 组织内存编辑和导出，`CollagePreview` 用原件及同一矩形/crop语义渲染，`CollageSequence`、`CollageTools`、`CollageExportDialog` 分别承担选片、工具与输出设置。预览的contain始终完整居中，cover按max(cell/source)×zoom缩放，offset 0–1定位溢出空间，与Rust合成契约一致。前端不使用Canvas截屏作为成片源。Rust通过图库的原件读取接口逐张读取来源照片，在RGB画布上按alpha与背景合成并直接编码PNG，同尺寸原图或裁片跳过重采样；避免同时保留整幅RGBA画布及RGB转换副本。输出与来源像素上限均为160MP，原件仍服从现有解码器的格式及内存限制；错误明确返回，不降采样重试。

`src/lib/collage-types.ts`、`collage-api.ts` 定义并调用 `export_collage_png`。Rust 按稳定 ID 读取同图库的来源照片，导出 IPC 只返回最终文件路径。相簿和候选取舍流程独立于导出。工作台经 `LibraryWorkspace` 向 App 上报 dirty/busy，复用现有导航与关闭保护；相簿滚动、选择及来源上下文保留在父工作区。目录窗口取消和生成失败均保留编辑与输出设置，成功返回来源相簿并短暂提示实际文件名。原件修订通过预览节点 key 重新读取，读取失败明确显示。

策划和拼图共享 `src/lib/export-directory.ts` 的系统目录选择器，以及 `png_export.rs` 的 PNG 文件写入。后端确认目录已存在并使用绝对路径，将文件名规整为单一文件名。文件创建使用排他模式，遇到同名项追加序号，写入失败时清理本次新文件。

## 拍摄策划

`src-tauri/src/planning.rs` 负责当前图库策划的层级文档、CRUD、事务与引用校验。`shoot_plans.document_json` 保存版本化v2全案、Part、目标画面和逐图参考意图；同一照片可以多处引用，结构节点具有稳定独立ID。`shoot_plan_photos` 保存按全案/Part/画面顺序首次出现的照片ID并集，供外键及备份引用保护；加载和恢复严格核对其与文档一致，不把错配当成空参考。

执行日期 `executionDate` 存于 v2 文档，为无时区的 `YYYY-MM-DD` 公历日期，独立于原 `shootDate` 自由文本。历史缺字段按空读取与恢复；非空日期须合法，新保存必须有合法日期。首页对已加载和刚保存的策划使用相同的日期排序规则，无日期时置底。

旧schema没有document_json列时，在一次事务中增加列并迁移全部v1记录；已存在该列的库不得因NULL、坏JSON或未知版本重建内容。旧造型、光线、镜头清单归入「原拍摄安排」Part，备注归入执行准备，旧有序图片归入全案参考；保留策划ID和时间，不猜画面关系。新保存清空废弃旧内容列，不从旧字段复活已删内容。恢复旧备份采用同一迁移与validate_all，部分结构或损坏文档明确拒绝。删除整份策划时复用图库引用检查，原件保留。

`planning_export.rs` 验证 PNG 内容、大小及像素限制，再将成品写入用户所选目录。`src/lib/planning-types.ts`、`planning-api.ts` 定义层级数据契约、限额与 IPC；`src/features/planning` 组织列表、阅读、编辑和长图。持久化仍完整保留全案/Part/画面的参考绑定和顺序；当前UI与导出仅展示Part场景图片及相邻意图，全案与镜头旧引用不删除、不迁移，非空意图转为相应区域内的纯文字参考要点。Canvas按原图与文本测量渲染，不截应用DOM；缺图和超限拒绝整个导出，不静默漏项。工作区沿用App dirty/busy导航和关窗保护。

场景（内部Part）的历史`shotList`自由文本继续保留在持久化契约和`inputOf`编辑副本中，参与含内容删除保护及原有备份；前端不提供填写入口，不参与阅读、搜索和PNG导出。镜头清单仅以`shots`结构化条目呈现；空`shots`显示“暂无镜头”，不因旧`shotList`非空隐藏空态。已知旧v2缺字段时serde默认空串；v1旧shot_list直接迁入该字段，不猜已有v2description内容。每场景3张参考仅在新保存时校验；list/validate_all及备份恢复保留历史合法超限引用，完整结构校验和有序照片并集约束不弱化。前端选择器限制新选3张，不slice旧图。

场景新增`focalLength`自由文本，Rust serde缺省空串并参与校验，前端新建、输入归一化、搜索及PNG通过场景字段表贯通；不引入焦段枚举或额外存储层。全案新增`styling`/`props`/`equipment`三项固定准备，通过`sharedFields`统一前端标签、输入归一化、搜索与导出；Rust三字段分别serde(default)，v1全案补空，不提升或拆分旧`part.styling`；旧引用并集与SQL废弃列清空规则不变。场景既有`timeWindow`在界面与PNG统一称为“拍摄时段”，置于场景标题区，页面和PNG参数区不重复，长文本完整换行；复用原有数据、限额和搜索链路，不新增字段或推导时间。界面按独立场景卡片组织：标题要点、显式“参考图”“拍摄参数”“镜头清单”三区，上区图与参数并排、下区全宽纯文字清单；参数统一单列对齐；镜头在固定阅读列内按名称/优先级、主拍法、单列标签详情、旧参考要点纵向组织；所有已填拍法直接可见，不使用details/summary。PNG内容模型显式表达章节起止、场景标题与时段、分区及标签字段；先测量图文与章节，再绘制连续白纸、场景前浅细线与内容，不根据文案推断结构，不绘制卡片背板或轮廓。全案整组准备前置且只出现一次，每场景按标题要点、参考图、拍摄参数、文字清单垂直组织，不输出全案及镜头图片。导出参考图最多两列，第三张及历史超限图片保持半列宽续行；按独立单元格测量、逐张解码绘制，文字与各自图列相邻，几何和照片比例保持一致。
