# 相簿封面取景交互

## 本轮方案

场景：从收藏或作品相簿右击一张有效照片，调整首页 3:2 封面的构图；不改变原件、照片墙或其他相簿。沿用现有 `AlbumCover` 偏移及缩放持久化结构和右键入口。

舞台采用中性深色，与现有弹窗、按钮、滑块及首页卡片共享视觉语言。固定 3:2 取景框居中，原图等比铺满框；框外照片压暗但保留可辨内容，框内不叠蒙层、不改变照片色彩。只在拖动期间显示细三分线，松手及取消即隐去。照片承担主要视觉重量，不增加常驻教学文字。

保留方向键、Shift 加速和缩放滑块；支持 WebKit `gesturestart/change/end` 及浏览器 Ctrl+滚轮，限制为 1–3 倍。所有缩放围绕取景中心保留主体位置，碰到原图边缘时才约束构图以避免露底。「重置」回到居中、最小铺满。取消与关闭不保存，保存完成后由既有流程卸载弹窗；保存中禁止重复操作及关闭，错误显示于操作区。

宽窗右侧使用首页的 `album-open`、`album-cover`、标题及数量类名呈现实时封面卡片，内容来自当前相簿名和有效照片数。窗口宽度不超过 1100px 时切为单列，默认收起卡片，按需展开；此断点覆盖 Tauri 的 920px 最小窗口。窄窗弹窗宽度同时按可用窗口高度收紧，确保 930×620 下默认收起时取景、控件与保存按钮完整显示；展开预览后沿用弹窗纵向滚动，保存按钮仍可滚动到达。预览与舞台共用已读取的原图及构图，不请求高清封面生成。加载或原图错误期间禁止编辑、预览与保存；仍可关闭。

## 验收依据

- 计算回归：横、竖、方图拖动边界；缩放前后中心像素位置；缩放极值、边缘约束和重置。
- 行为回归：右键目标不受批量选择影响；加载/错误禁用；拖动三分线；方向键、滑块、Ctrl+滚轮及 WebKit 捏合；真实名称与有效数量；取消、保存失败、重试和保存中关闭限制。
- 原生与视觉验收由独立验收者执行：混合比例真实摄影、宽/窄窗口、框内色彩、框外辨识度、实时预览、触控板捏合、键盘路径、关闭无残留。构建与自动测试不替代此验收。

## 验证记录

定向 Node 回归已通过：`album-cover-geometry.test.mjs` 与 `library-workspace-album-home.test.mjs` 共 36 项，覆盖横/竖/方图的缩放中心及边界、完整源图舞台尺寸、手势事件、重置、三分线、读取失败、取消、保存失败重试和真实卡片数据。随后新增 930×620 窄窗样式定向回归并单独运行通过，按实际入口的级联顺序将 `library.css` 放在 `index.css` 基础控件规则之前；预览按钮采用局部双类选择器，避免基础 `.text-button` 的显示规则覆盖。此回归检查真实样式下的预览入口、默认收起、展开、弹窗纵向滚动，以及 1200px 宽窗常驻预览。Happy DOM 无真实布局，此项不证明舞台和按钮的原生像素位置。手势测试为合成事件，不替代原生触控板实测。原生、动态和设计结果由主代理记录；类型检查、构建与应用运行由主代理统一通过 Avenil 执行。

### 2026-11-07 原生验收

主代理独立于实现者，通过 Avenil 构建并运行 macOS release 隔离实例 `app.foliune.cover-interaction-review`。最终资源为 `index-C39gKr36.js` / `index-zMmJndcX.css`；取景相关四份实现文件的指纹与最终构建前清单一致。图库从既有验收库复制，包含 74 张摄影及测试材料副本，不访问用户生产图库。

在 1320×880 和 930×620 点窗口实际检查方形天空、竖幅植物和横幅风景。框内保持照片原色、框外暗部仍可辨，取景框与卡片的主体位置一致；宽窗只显示常驻卡片，窄窗显示预览开关，收起时取景、缩放、重置及保存完整可见。窄窗展开后实际滚动到卡片与保存按钮。通过滑块调至 200%、拖动、重置、保存，再次打开确认回显 200%；取消及 Escape 后弹窗卸载并恢复原照片焦点，无遗留蒙层。

前端全量 222 项回归通过；新增响应式及级联检查随后单独通过。最终类型检查、Vite 生产构建、macOS release 打包和独立代码审查通过。构建仍有已有的混合导入和大 chunk 提示。验收前后只有 `album_covers` 表变化，74 张原件和 74 张缩略图哈希完全一致，SQLite 完整性与外键检查通过。

证据在 `.build/verification/album-cover-interaction/`，包括最终宽窗方形、窄窗收起/展开、横幅截图，构建日志、测试日志、源码指纹和图库前后审计。保留照片与取景的主次，复用现有深色材质和首页卡片语言，是本轮对“高级”与“设计感和质感”的具体落实；静态及操作检查不等于用户已认可最终审美。
