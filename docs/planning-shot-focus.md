# 镜头清单的阅读焦点

2026-11-03，用户指出上一轮镜头清单仍然横向散开，看不出首先读什么。本轮只重排应用内镜头清单，保持场景标题、参考图、拍摄参数、全案其它区域及 PNG 导出不变，不改数据字段。

## 方案

镜头清单使用左对齐、最大 860px 的阅读列。每条镜头以细编号栏定位，正文统一起点：16px、500 字重的名称先建立主题，同排用小而中性的优先级标识表达必拍或备选；14px 主拍法紧随名称。构图、姿态、光线、情绪全部按单列标签和值接续，标签列固定 64px，禁止双列横向跳读。旧参考要点完整置后，沿用同一标签列，以较轻的 12px 字色与字号降低权重。空字段在阅读态不占空间。

每镜头不增加嵌套卡片，以标题、主拍法、细节的字体层级和条目间浅线形成节奏。场景补充清单在结构化镜头后回到场景起点，以明确组距、顶部浅线和短标签单独收尾，避免归入最后一个镜头；只有自由清单时直接展示内容，不重复标题。

编辑沿用阅读顺序和相同阅读宽度，复用既有输入、优先级、排序和删除控件。全部字段保持挂载，保留清空续写、稳定 ID、新增焦点、dirty、容量及删除确认行为。颜色、控件及材质沿用中性深色体系，排版规则仅作用于镜头区。

## 验收依据

类型检查及现有 38 项策划内容、PNG、断行 Node 测试通过后冻结，交由独立代码审核与 Avenil 原生验收。原生检查宽窄窗、长名称和长拍法、多镜头及缺省字段，确认名称→拍法→单列细节→旧要点的视线连续、场景补充归属清楚；检查编辑清空续写、新增焦点、排序、删除取消和放弃修改。截图、实例与限制由主代理补充，构建通过不代表视觉通过。

本轮以稳定阅读起点、明显而克制的文字主次和完整内容落实高级感及设计质感；不添加装饰底板、说明文案或新交互。
