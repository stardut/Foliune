# 移除人工密度场，恢复系统深色玻璃

2026-10-30，用户要求彻底去掉雾状斑块，保持当前深色，材质须自然通透而非渐变/云雾。本轮从根因移除人工SVG密度场及shell伪元素，停止用静态光影补偿系统透光。先以同色`.88`均匀遮光对齐此前约`.895`有效深度，保留真实native HUD和细内缘；如需调整原生材质，以实际运行比较作为依据，不凭材质名称判断。

不动照片/白纸/业务/布局和B控件。验收区分去图案、深度、壁纸参与三项。均匀桌面本身缺少明暗，真实毛玻璃不保证产生固定光影；不能为避免平淡重新加入人工花纹。检查宽窄首页、弹窗与已有画册，以同窗截图辅助比较深度，桌面透光需要实际合成或用户实看。用户目标保持有效，不把代码清理等同最终设计通过。

## 清理实现

删除`index.css`的`.app-shell::before`及`public/textures/glass-transmission.svg`，`--surface`改为统一同色`.88`。未新增渐变/云雾/噪声/白色光斑，原生HUD/透明宿主保持。源与dist均无该SVG，源码冻结在`.build/verification/native-smoke/source-freeze.json`。

前端类型/生产构建与macOS release app构建通过，资源`index-BiepHYmh.css` / `index-Cf4A2utx.js`，Avenil独立实例PID9545。原生首页`hud-wide.png`中人工斑块已消失，背景保持深黑；此单窗图接近均匀，不能当桌面透光证据。用户实窗反馈“深度合适，但仍像纯色”。

## 原生接口边界

只读本地Tauri/window-vibrancy/Tao代码确认材质与Dark外观继承正常，公开配置没有黑位/对比度/透光强度独立控制项。`.88`遮光仅保留约12%的系统底色变化，因此保深度与明显透光有客观权衡。可供控制变量比较的未试候选为`popover + Dark + active`，未弃用且当前支持，不凭名称断言比HUD更深/更透；尚未据此修改原生配置。弃用的`ultraDark`不作为正式解法。

## 验证结果与未完成边界

主代理实际操作宽窄收藏首页、弹窗打开取消、已有3页手工画册打开，未创建/修改业务数据，最后恢复宽窗首页。最终证据`native-smoke/{final-wide,narrow,dialog,book}.png`，宽2640×1760、窄1842×1242。

与前版相同三个空白区域合并灰度均值20.856→21.001，深度基本对齐（只代表采样区域）。人工空间明暗已消失，统一底约21灰阶；不把单窗图的均匀性等同原生透明失败，也不当真实透光通过。

独立源码与全部代表图审查通过“去人工云雾/渐变、保持深色、内容隔离”的范围：照片、标题、计数、控件、dialog焦点/边界以及画册白纸/字幕/页码清楚，没有确认需修问题。用户随后实窗反馈“深度合适，但仍像纯色”，因此自然通透项未通过，继续[原生材质受控对照](native-popover.md)；没有擅自把另一种native材质候选当正式方案，也没有重新叠加人工纹理。

本轮未重测图库中末段、完整动效、导出、其他平台、正式分发或性能。整体高级感及自然通透目标未仅凭清理和截图判通过。
