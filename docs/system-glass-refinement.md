# 系统毛玻璃与连续背景修订

## 用户反馈与本轮目标

2026-10-30，用户明确指出上一版并非真正系统毛玻璃，背景色块过多、线段分割造成割裂，配色未达到期望。上一版的阶段验收不能代表用户认可；本轮以此反馈修订样式方向。

本轮采用真正可透出桌面壁纸的 macOS 系统材质；统一连续、中性的烟灰深色基底，移除棕绿渐变、多重照片托底、重复卡片边框与横向装饰分割线。壁纸自然参与色温，照片本身保持忠实。

## 实施方案

- 宿主使用 Tauri 已内置的 macOS vibrancy，经 NSVisualEffectView 的 BehindWindow 模式渲染；WebView 与页面根节点透明，页面仅施加一层适度中性深色 tint。
- macOS 标题栏与内容连贯，保留系统交通灯、拖动和窗口控制；其它平台不冒称支持同样材质。
- 顶部导航与内容共享基底；通过间距和排版建立主次。相簿去多重外框，功能分区去重复背景和装饰线。控件、必要选择反馈及临时浮层仍具有清晰边界。
- 顶栏文字须在亮壁纸、亮照片附近清晰；照片不在导航下方造成明暗干扰。若改变滚动容器，必须检查照片墙分页、滚动恢复、焦点与画册可用空间。
- 画册纸张、独立导出、照片像素、数据与现有业务行为保持各自边界；已有窄窗创建弹窗修复保留。

## 验收

在独立测试实例验证透明宿主与系统材质实际生效，观察桌面不同底层内容/窗口位置下的透光变化，不能只凭配置或CSS称为系统毛玻璃。保留宽窄窗、相簿/照片墙、设置、创建/编辑/阅读等关键截图及交互证据。独立审查统一性与可读性；构建通过与设计通过分别记录。

## 实施与验收结果

- macOS 专用 `tauri.macos.conf.json` 启用透明宿主、单一 `underWindowBackground` 系统材质及 Overlay 标题栏；当前 Tauri 2.11.5 经 window-vibrancy 调用 NSVisualEffectView 的 BehindWindow 模式。页面根节点透明，外壳仅保留一层 40% 中性深色 tint；其它平台主配置仍为不透明窗口。
- 移除棕绿柔光、顶部独立底色和横线、相簿重复外框与托底、设置及编辑区重复面板；控件统一银灰。内容在导航下方内部滚动，防止亮照片干扰导航。
- 用户在本机明确回复“能看到壁纸透光”。这与源码机制共同作为本机系统材质生效依据；工具单窗口截图呈平灰，不能作为桌面最终合成的直接证明。系统“降低透明度”和“增强对比度”经 UI 只读核对均关闭，未修改系统偏好。
- 实际检查照片墙末尾、切设置页头、重新进入相簿首段、放大挑选返回，以及约949×621窄窗的已保存3页手工版编辑器和创建弹窗；纸张、字幕和操作区保持完整。独立验收核对截图、代码及冻结指纹，已审范围通过。
- Overlay 引入的播放器返回按钮靠近交通灯问题已定点修正：共享28px安全带，顶部控件40px、照片舞台起点90px，宽窄窗原生复验和独立截图审查通过。
- 类型检查、前端生产构建、`cargo check --locked`、macOS release `.app` 构建通过。独立测试库仍为65照片、4相簿、67成员关系、2画册、3版本，原件哈希未变。

证据保存于 `.build/verification/system-glass/`，包含 `wall-tail.png`、`settings-after-tail.png`、`wall-reenter-top.png`、`editor-narrow.png`、`final-create-narrow.png`、`final-player-wide.png`、`final-player-narrow.png`、`source-freeze.json` 与 `final-integrity.json`。截图窗口尺寸以文件元数据和实际内容为准，部分捕获存在白色画布/倍率差异，不能仅凭文件名判断宽窄。

## 验证与分发边界

本轮确认的是本机壁纸透光、已覆盖的布局与交互，最终审美认可仍依据用户反馈。窗口空白拖动在系统居中后执行成功，但工具未提供几何位移证据，不声称完整手势验收；窗口系统菜单与窄窗尺寸调整已实际操作。应用内全屏按钮本次显示“当前系统窗口不支持全屏，请使用系统窗口的全屏入口”，未修改其原有逻辑，本轮不宣称全屏通过。

减少动态效果仅确认系统当前关闭，未切换偏好实测；Windows、独立HTML导出、外部AI和正式分发未实测。当前Tauri 2.11.5透明机制要求`macos-private-api`，其本地源码明确该API不适用于Mac App Store分发；不据此宣称上架通过。系统材质初始化路径存在上游忽略返回值的限制，本轮不增加额外依赖或把投递成功误记为透光成功。
