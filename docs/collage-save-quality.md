# 拼图保存反馈与清晰度修订

2026-11-02，用户明确要求移除保存后占据照片墙的一整行信息，只在右上角短暂提示保存成功；同时指出保存后的拼图清晰度很差，要求保持原图清晰度，不擅自压缩。

## 范围与依据

保存后回原相簿并保留有效选择和滚动的业务保持，移除相簿名、查看及关闭入口和相关定位状态。成功反馈采用沿用现有烟黑浮层变量的小型右上角消息，约3秒直接卸载，不占布局、不抢焦点，进入编辑、切相簿和卸载时清理。此修订替代此前的常驻保存横条及查看入口。

清晰度缺陷已在真实布局函数的回归测试复现：旧逻辑把2400参考宽度用于限制成片，再取各图缩放需求的最小值，导致大图降采样，小图还会进一步缩小整幅输出。6000×4000来源在两图组合中实际采样倍率约0.26375。后端读取的是原件并输出PNG，问题不能仅靠“无损格式”解决。

修订将预览参考几何与保存尺寸分开；默认按全部来源有效取景所需的最大采样倍率计算输出。裁切与缩放仍服从用户当前编辑，不改原件。资源边界明确报错，不静默降低分辨率；用户手动调小尺寸时显示降低分辨率，并可恢复默认原图尺寸。已有低分辨率成片没有自动恢复细节的依据，不反向改写已有文件。

## 实际验收

此前[首轮拼图验收](collage-verification.md)中的小尺寸结果仅为历史记录，不作为本次清晰度修复通过的依据。

- 类型检查、前端构建、macOS release及Rust格式检查通过。布局回归28项、Rust拼图定点8项通过；棋盘及坐标纹理逐像素证明完整显示和zoom裁切在原生1:1时与来源完全一致，透明来源仍按所选背景合成。
- 160MP端到端资源测试单独运行通过：16000×10000 RGB PNG实际编码、导入和缩略图、候选到原子提交后尺寸不变。debug耗时81.05秒、最大驻留内存649,363,456字节；这是小来源加大画布样本，不作为复杂源的峰值或release性能结论。
- Avenil「Foliune 拼图验收」独立实例 `app.foliune.collage-review`，65张真实摄影测试原件。四图网格默认6302×6302，手动改2000时出现降低分辨率，点击恢复回到6302，随后以默认值保存到「拼图作品 · 验收」。
- 实际文件为6302×6302、RGB PNG、33,100,331字节，完整解码尺寸与数据库一致。旧默认同组网格仅1612×1612；新默认不受最小768px来源牵制。四图自适应10586×11281、长图3127×13203也通过纯函数逐图采样密度校验；本轮原生只保存网格，不将另外两种称为本轮原生保存实测。
- 原生捕获右上角「保存成功」，随后自动消失；来源相簿及四选保留，无旧横条。保存前、成功显示时、消失后的第一张照片同一区域逐像素一致，支持照片墙未被推移；其他尚在读取图片的差异不作为位移判断。
- 独立重算65份来源原件SHA-256全部一致，来源相簿active65。正式照片由69增加至70，仅新增本次成片；未替换已有低分辨率拼图。
- 最终release资源 `index-0YLaF84p.js` / `index-Dq6n-C-g.css`，经Avenil重启后可搜索并打开新高清成片。保存与toast证据来自仅差一条ARIA标签修订的前一产物 `index-qVQmZJTd.js`；该修订仅移除预览参考像素的错误播报，保存、像素、计时与视觉规则相同。

证据位于 `.build/verification/collage-toast/`：`default-save.{txt,png}`、`success.{txt,png}`、`after-dismiss.{txt,png}`、`native-result.json`、`source-resolution.json`、`wall-position-check.json`、`final-native-view.{txt,png}`及release构建日志。

独立验收者核对本轮变更、重跑28项布局测试，并检查实际PNG、截图与数据，未发现确定需修项。成功反馈使用既有浮层材质和克制图标，原图像素决定成片清晰度；本轮设计及质感结论有原生摄影依据。

上限统一为32768px单边、160MP；超限明确提示，只有用户显式调整尺寸才降分辨率。Windows、系统减少动态效果及复杂大图性能本轮未实测；ICC色彩转换沿用此前边界，不将分辨率修复冒称色彩管理修复。
