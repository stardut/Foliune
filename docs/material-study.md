# 首页材质关系对照原型

2026-10-30，用户确认暂停仅靠原生材质/透明度反复校准，先做材质层级对照。问题是：同一摄影首页在浅、深、复杂背景下，怎样稳定保持深度，并让窗口、内容承托与操作控件形成清晰且克制的材质分工？

本轮只制作独立只读原型，正式React/CSS/原生配置、运行应用和图库不动。原型位于`apps/desktop/prototypes/material-study/`，由Avenil管理本地静态服务；读图库仅用于复制既有测试照片缩略图，不接数据库写入，不使用用户私有原件。

## 三种方向

- A：当前单层玻璃的近似基线，窗口/承托/控件主要沿用同一种环境参与方式，暴露均匀浅背景时的平与灰。
- B：熏黑玻璃。外壳、轻微照片承托和精细操作表面各自承担职责，以边缘、顶光和短阴影建立层次，避免斜向大渐变和彩色光斑。
- C：画廊材质。外壳低幅度环境参与，摄影内容区更中性、稳定，封面尽量干净，以控件和内容的不同表面关系呈现质感。

同一导航、相簿顺序、封面及布局，明确覆盖prototype技能默认的结构大改要求，以免把版式好坏混入本轮材质比较。支持`?variant=A|B|C&scene=light|dark|color`、界面按钮与键盘切换；所有业务交互为只读或内存示意。原型工具条与产品界面分开标识，不加入正式应用。

## 验收与边界

检查方案/场景切换和URL刷新、横竖方与空封面完整构图、宽窄可读性、弹窗关闭与键盘路径。视觉检查三方向是否有实质材质职责差异、浅色场景是否依然沉稳、照片有无叠色。无生产源码变化，不重复正式应用全量构建或Rust测试。

浏览器只模拟材质关系，不能证明NSVisualEffectView或桌面壁纸透光，也不代表最终原生完成。用户选择方向后再将胜出原则实现为正式组件，并用真实原生浅/深/复杂背景验收。本轮不创建git分支、commit或issue；遵循用户Git边界，原型清楚标为临时文件，后续按实际选定方向处理。

## 原型与检查结果

原型为143行HTML和3张既有测试相簿缩略图，无远程资源、数据库连接、IPC或持久化。运行地址`http://127.0.0.1:1438/?variant=B&scene=light`，由Avenil服务“Foliune 材质对照原型”（`b911ae9d-2ac7-490c-acd0-2d3e4d507b7e`）管理，支持直接双击HTML；上下文在目录内，不接正式应用路由。本轮用户要求隔离对照且正式应用为原生数据入口，故选择独立原型，避免将临时切换控件混入正式业务。

内置浏览器连接不可用后，使用本地Chrome实际检查：A/B/C浅色切换、B深色及复杂场景、C复杂场景键盘切换与刷新保持、原型新建输入ArrowLeft不切方案、Esc关闭与焦点恢复、窄窗940×760相簿及竖幅只读预览。测试后清除视口覆盖，保留B浅色页。页面内滚动承载超出高度的封面，图片使用contain保持比例。

独立审查发现dialog位于window兄弟节点，按钮材质变量未继承；已将三个按钮token连同modal背景同步到所有dialog。刷新后实际弹窗按钮背景、边框、阴影恢复，取消可关闭，未建立真实相簿。证据在`.build/verification/material-study/`：`A-light.png`、`B-light-final.png`、`C-light.png`、`B-dark.png`、`B-color.png`、`C-narrow.png`、`dialog-final.png`。正式源码、宿主配置指纹与本轮前一致（`result.json`），未运行无关正式构建或Rust测试。

B的承托和控制层更明确，C的中性内容区更稳定但顶部边界明显，均为可比较的取舍。用户随后明确选择B并要求落实实际应用，见[B方案原生落地](material-b-implementation.md)。此结果只证明原型可检查与已覆盖交互，不证明真实系统玻璃、全部场景矩阵或最终审美通过。
