# 应用文字选择修复（2026-11-01）

## 现象与方案

用户报告字标、导航与相簿标题出现浏览器原生灰色文字选区。macOS 原生验收窗口在照片墙按 Cmd+A 可重现相同现象，照片同时被选区蒙灰，证据 `.build/verification/text-selection/before.png`。

这属于浏览器文档选择进入桌面应用外壳，不是照片业务选择或键盘焦点问题。范围明确，采用原生实际操作前后对照作为本轮诊断反馈；不为单纯 CSS 行为增加模拟实现的测试、运行日志或键盘拦截。

外壳默认不参与原生文本选择，兼顾 WebKit 的前缀行为；输入框、文本域、实际可编辑区域、画册纸张和必要可复制路径/诊断信息明确允许选择。保持视觉样式、照片业务选择、右键菜单、键盘路径、窗口拖动与独立导出不变。

## 验收依据

相同原生窗口、同一照片墙，Cmd+A 或拖动标题文字不再出现外壳选区/照片蒙灰；输入框可全选编辑，路径信息可选择，管理菜单及照片浏览仍可用。纸张与导出边界另做源审，未实测项须明确标注。

## 实施与验证

仅修改 `index.css`、`SettingsWorkspace.tsx` 和 `PhotoPlayer.tsx`：外壳默认双 user-select:none；字段、可编辑区域、纸张、路径和诊断/AI结果正文双text例外；设置路径加语义class，播放器错误正文包span以区别关闭按钮。未更改配色/字号/间距、业务选择、菜单、焦点、窗口拖动或任何按键处理；独立导出使用自身样式且不含app-shell，不受新规则作用。

类型检查及 macOS release `.app` 构建通过，资源 `index-B3-A7-n4.css`、`index-D6LZOmtd.js`；仅既有 api.ts 动静态导入分包提示。独立源码审查未发现确认阻塞项。

原生实例为 `app.foliune.dark-review`，独立65张摄影/4本相簿图库，2026-11-01：

- 修复前：照片墙 Cmd+A 精准复现整页选区，字标、导航、标题灰底，照片蒙灰；AX报告原生 Selected text。`before.png` 为3024×1888截图。
- 修复后：同一相簿照片墙 Cmd+A，AX无 Selected text，实际截图无灰选区及照片蒙灰；`after.png` 为2640×1760。重启后的窗口尺度不同，因此仅比较选择行为，不作为版式前后比较。
- 新建相簿表单：输入 `Selection check`，Cmd+A 后 AX报告完整选中文本；替换为 `Replaced` 后值正确。简介文本域 `Description selection` 也能完整全选。均取消，无保存或新建图库记录。最初工具 typeText 未送入文字，改用原生 paste 完成验证，不将空输入当通过。
- 设置图库路径三击后 AX报告完整路径选中，`path.png`保留证据。未读取或更改系统剪贴板验证复制粘贴，实际复制操作不冒称实测。
- 相簿卡片右键仍显示信息/删除，Esc取消后焦点回原卡片。

证据目录 `.build/verification/text-selection/`。纸张选择和独立导出本轮为源码边界审查，未重新打开原生纸张/导出文件；错误、AI正文选择为源码检查；未实测Windows、真实读屏或跨平台拖选。普通拖选未另测，以原生Cmd+A同症状前后对照及CSS作用边界为本轮结论。

修复让导航和作品保持清晰，避免原生文档选区破坏深色界面的层级；不靠隐藏选择颜色掩盖可选性，也不关闭输入或文档内容的正常选择能力。
